# Archive of 13 October 2026 — everything the console held before the clean slate

Moved here on 2026-10-13 at Tiran's direction (*"clear the database so I can start new runs …
clearing out any findings and runs that happened in prior iterations of the app, didn't track
the right metrics, don't have a recording, etc — so we have a clean slate"*). **Nothing was
deleted.** Each folder is exactly what sat at the path in the right-hand column, moved with
`git mv` where git tracked it and `mv` where it did not.

| here | was at | what it is |
|---|---|---|
| `runs/` | `eval/runs/` | 139 v2 run directories with a manifest, plus 28 that recorded nothing: the C0 pilot (September 2026), the nine-command parity campaigns (14 September), and the console-era `cat` runs (24 and 29 September). Only 4 have a terminal recording. None records cached tokens, the v2 commit, the guest OS or the coreutils version (task 014 phase 2 adds those). |
| `v1_runs/` | `eval/v1_runs/` | 24 v1 runs the console started (29 September and 13 October): `generate`, `syntax-spec`, `trace`. None of the live `syntax-spec` runs was metered. |
| `metrics.db` | `eval/metrics.db` | the per-turn telemetry database for the runs above. `eval/metrics.db` was rebuilt empty with `caruca-v2 metrics rebuild`. |
| `campaigns/` | `eval/campaigns/` | **the only part git never tracked**: the ledgers of `c0_*` and `p1_*`, holding every scored cell the parity study's figures and the console's verdicts came from. Kept untracked here too (`.gitignore`: `eval/_archive/**/campaigns/`). |
| `parity_diffs/` | `eval/parity_diffs/` | the per-command drill-downs the Compare screen quoted for the nine. |
| `findings/` | `ai_docs/analysis/findings/` | the twelve finding files backfilled from the parity study and the E0 report, with the numbers the console re-checked. |

**What was not moved, and why:** `eval/v1_configs/` (v1's own configuration expansions — the
*inputs* v2's step 3 reads, generated by v1 and not a result of any v2 run); `eval/e0/` and
`eval/pash_scheduling/` (not pipeline runs); v1's traces and annotations under
`$CARUCA_V1_ROOT/caruca/outputs/` (v1's side, in v1's tree).

**To read these from the console or its tests,** set `CARUCA_EVAL_ROOT` to this folder: the
console's `repoPaths()` then resolves runs, v1 runs, campaigns, the database, parity diffs and
findings here instead of under `eval/` and `ai_docs/analysis/findings/`. The console's test
suite does exactly that (`console/vitest.config.ts`), because its readers are tested against
these real directories.

**To restore any of it,** move the folder back to the path in the second column. The
documents that cite these runs by id (`ai_docs/analysis/v1_v2_parity_study.md`,
`e0_artifact_pinning.md`, the status reports) are unchanged; their run ids resolve here.
